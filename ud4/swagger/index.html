    🧭 Swagger (OpenAPI) con Spring Boot

    ✅ 1) ¿Qué es Swagger / OpenAPI? 🧩

    • OpenAPI es un estándar para describir una API (endpoints, parámetros, respuestas, DTOs, errores…).
    • Swagger UI es una interfaz web que lee esa descripción OpenAPI y te deja:
    • ver todos los endpoints ordenados,
    • probarlos (GET/POST/PUT/PATCH/DELETE),
    • ver DTOs, validaciones y respuestas.

    👉 En Spring Boot solemos usar springdoc-openapi, que genera automáticamente la especificación OpenAPI a partir de tus controladores.

    📦 2) Activar Swagger: dependencia + levantar /swagger-ui 🚀

    2.1. Añadir la dependencia (Gradle) 🧱

    En tu build.gradle:

    implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui:3.0.1'

    Solo con esto ya aparece Swagger UI al levantar la app.

    2.2. Arrancar la aplicación ▶️

    • Desde IntelliJ (botón ▶️)

    2.3. Abrir Swagger UI 🌐

    En el navegador:

    • ✅ Swagger UI: http://localhost:8080/swagger-ui/index.html. Es una página web que te enseña la documentación y te deja probar endpoints.
    • ✅ OpenAPI JSON: http://localhost:8080/v3/api-docs. Es un JSON (un documento de texto) que contiene la descripción completa de tu API en formato estándar OpenAPI.

    Si tu puerto es distinto, cambia el 8080 por el que estés usando.

    ⚙️ 3) Ajustes básicos (título, versión, descripción) 🪄

    Tienes dos formas: rápida (properties) o completa (bean OpenAPI). Nosotros lo haremos de la forma rápida.

    Opción A) Rápida: application.properties 🧷

    En src/main/resources/application.properties:

    # Controla si el botón “Try it out” (probar el endpoint) está activado por defecto.
springdoc.swagger-ui.try-it-out-enabled=true

# (Opcional) Cambiar rutas, sino se quedan las de por defecto del punto 2.3
# springdoc.swagger-ui.path=/swagger
# springdoc.api-docs.path=/api-docs

    Esto sirve para activar/desactivar o cambiar rutas.

    🧩 4) Anotaciones clave 🧰

    🔹 @Tag

    Sirve para organizar y agrupar los endpoints:
    - name: un nombre corto - description: explicación ampliada (se ve en la agrupación)

    🔹 @Operation

    Sirve para describir el endpoint:
    - summary: una frase corta (lo que aparece en la lista) - description: explicación ampliada (lo que se ve al abrir el endpoint)

    🔹 @ApiResponse / @ApiResponses

    Sirve para documentar qué devuelve el endpoint y con qué códigos HTTP.

    🔹 @Parameter

    Sirve para documentar parámetros (query params, path variables…):
    - descripción, ejemplo, requerido, allowables…

    🔹 @Schema

    Sirve para documentar DTOs (y modelos de error):
    - descripción, ejemplo, formato, restricciones.

    🏷️ 5) Tags por controlador (orden y organización) 📚

    Sin tags, Swagger muestra endpoints “sueltos”.
    Con tags, queda ordenado por secciones como:

    • Flights
    • Passengers
    • Bookings
    • Seats

    5.1. Tag simple en un controlador 🎯

    import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.bind.annotation.RequestMapping;

@Tag(name = "Flights", description = "Operations related to flight management")
@RestController
@RequestMapping("/flights")
public class FlightController {
    // endpoints...
}

    👉 Ahora Swagger crea un bloque “Flights” con todos los endpoints de ese controlador.

    5.2. Describir un endpoint concreto ✏️

    import io.swagger.v3.oas.annotations.Operation;

@Operation(
    summary = "List flights",
    description = "Returns all available flights (optionally supports pagination and sorting)."
)
@GetMapping
public List<FlightResponse> getAll() {
    // ...
}

    ✅ Esto mejora muchísimo la API, la hace más legible.

    🧱 6) Mostrar DTOs bien (campos, validaciones y ejemplos) 🧠

    Swagger ya “ve” tus DTOs, pero puedes mejorarlos con anotaciones @Schema y ejemplos.

    Lo ideal: que el alumno lea el DTO y entienda qué poner y por qué.

    6.1. DTO con @Schema (descripción + ejemplo) 🧾

    import io.swagger.v3.oas.annotations.media.Schema;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;

public record CreateFlightRequest(

    @Schema(description = "Flight code", example = "IB1234")
    @NotBlank
    String code,

    @Schema(description = "Origin airport ID", example = "1")
    @NotNull
    Long originAirportId,

    @Schema(description = "Destination airport ID", example = "2")
    @NotNull
    Long destinationAirportId
) {}

    ✅ Resultado: en Swagger verás el DTO más claro, con ejemplos por campo.

    6.2. Ejemplos completos en un endpoint (request/response) 🎁

    Puedes meter ejemplos “bonitos” con @io.swagger.v3.oas.annotations.parameters.RequestBody:

    import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.ExampleObject;

@Operation(summary = "Create a flight")
@io.swagger.v3.oas.annotations.parameters.RequestBody(
        required = true,
        content = @Content(
                examples = {
                        @ExampleObject(
                                name = "Ejemplo válido",
                                value = "{ \"code\": \"IB1234\", \"originAirportId\": 1, \"destinationAirportId\": 2 }"
                        )
                }
        )
)
@PostMapping
public ResponseEntity<FlightResponse> create(@Valid @RequestBody CreateFlightRequest request) {
    // ...
}

    📝 Nota: esto es opcional.

    ✍️ 7) Endpoint “bien documentado” 🧱

    ✅ Ejemplo: listar vuelos con paginación y ordenación

    import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.web.bind.annotation.*;

@Operation(
        summary = "Listar vuelos",
        description = "Devuelve una lista paginada de vuelos. Permite paginar y ordenar usando los parámetros estándar."
)
@ApiResponses({
        @ApiResponse(responseCode = "200", description = "Listado obtenido correctamente"),
        @ApiResponse(responseCode = "400", description = "Parámetros de paginación/ordenación inválidos")
})
@GetMapping("/flights")
public Page<FlightResponse> getFlights(
        @Parameter(description = "Objeto de paginación/ordenación (page, size, sort).", required = false)
        Pageable pageable
) {
    // ...
}

    🧯 8) Documentar códigos de respuesta Http (200/400/404/409...) 🔥

    La clave es que usar @ApiResponse indicando el modelo de error 🧾

        @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Flights retrieved successfully"),

            @PageableDefault(
                page = 1,

        return ResponseEntity.ok(flightService.findAllPage(pageable));
    }

    📄 10) Paginación y ordenación: cómo dejarlo bien documentado 📌

    10.1. Qué parámetros suelen usarse (estándar Spring)

    Cuando un endpoint acepta Pageable, Spring admite típicamente:

    • page → número de página (0, 1, 2…)
    • size → tamaño de página
    • sort → campo y dirección (puede repetirse)

    Ejemplo real: 

    GET /flights?page=0&size=10&sort=departureTime,asc&sort=code,desc

    10.2. Documentarlo 🧭

    Opción A (rápida): explicarlo en la descripción del @Operation

    @Operation(
  summary = "Listar vuelos (paginado)",
  description = "Parámetros: page (empieza en 0), size, sort (campo,dirección; repetible). " +
                "Ejemplo: /flights?page=0&size=10&sort=code,asc&sort=departureTime,desc"
)

    Opción B: documentar cada parámetro manualmente (si NO usas Pageable)

    @GetMapping("/flights")
public Page<FlightResponse> getFlights(
        @Parameter(example = "0", description = "Página (empieza en 0)")
        @RequestParam(defaultValue = "0") int page,

        @Parameter(example = "10", description = "Tamaño de página")
        @RequestParam(defaultValue = "10") int size,

        @Parameter(example = "code,asc", description = "Ordenación: campo,dirección. Se puede repetir.")
        @RequestParam(required = false) List<String> sort
) {
    //...
}

    🏁 11) Ejemplo completo

    @Tag(name = "Flights", description = "Operations related to flight management")
@RestController
@RequestMapping("/flights")
public class FlightController {

    private final FlightService flightService;

    public FlightController(FlightService flightService) {
        this.flightService = flightService;
    }

    /**
     * ✅ GET /flights
     * Soporta:
     *  - ?page=0&size=10
     *  - ?sort=departureDate,asc&sort=departureTime,asc
     *  - ?sort=basePrice,desc
     */
    @Operation(
            summary = "List flights (paginated & sorted)",
            description = """
                    Returns a paginated list of flights. Supports pagination and sorting.

                    Examples:
                    - /flights?page=0&size=10
                    - /flights?sort=departureDate,asc&sort=departureTime,asc
                    - /flights?sort=basePrice,desc
                    """
    )
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Flights retrieved successfully"),
            @ApiResponse(responseCode = "400", description = "Invalid pagination/sorting parameters")
    })
    @GetMapping
    public ResponseEntity<Page<FlightDto>> listarVuelosPaginados(
            @ParameterObject
            @PageableDefault(page = 1, size = 10, sort = "departureDate", direction = Sort.Direction.ASC)
            Pageable pageable
    ) {
        return ResponseEntity.ok(flightService.findAllPage(pageable));
    }

    // ✅ GET /flights/{id} -> 200 o 404
    @Operation(
            summary = "Get a flight by id",
            description = "Returns the flight details for the given id."
    )
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Flight found"),
            @ApiResponse(responseCode = "404", description = "Flight not found"),
            @ApiResponse(responseCode = "400", description = "Invalid id format")
    })
    @GetMapping("/{id}")
    public ResponseEntity<FlightDto> get(
            @Parameter(description = "Flight id", example = "10", required = true)
            @PathVariable Long id
    ) {
        return ResponseEntity.ok(flightService.findById(id));
    }

    // ✅ PATCH /flights/{id} -> 200 o 404
    // Patch parcial: solo aplicamos campos que vengan en el request
    @Operation(
            summary = "Patch a flight",
            description = "Partially updates a flight. Only fields present in the request will be updated."
    )
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Flight updated successfully"),
            @ApiResponse(responseCode = "400", description = "Invalid request body (null/invalid fields)"),
            @ApiResponse(responseCode = "404", description = "Flight not found"),
            @ApiResponse(responseCode = "409", description = "Conflict (business rule violation)")
    })
    @io.swagger.v3.oas.annotations.parameters.RequestBody(
            required = false,
            description = "Patch payload. Send only the fields you want to update.",
            content = @Content(
                    schema = @Schema(implementation = PatchFlightRequest.class),
                    examples = {
                            @ExampleObject(
                                    name = "Patch example",
                                    value = "{ \"status\": \"DELAYED\" }"
                            )
                    }
            )
    )
    @PatchMapping("/{id}")
    public ResponseEntity<FlightDto> patch(
            @Parameter(description = "Flight id", example = "10", required = true)
            @PathVariable Long id,
            @RequestBody(required = false) PatchFlightRequest req
    ) {
        return ResponseEntity.ok(flightService.patch(id, req));
    }

    // ✅ GET /flights/search?from=MAD&to=BCN
    @Operation(
            summary = "Search flights",
            description = "Searches flights by origin and destination airport codes (optional filters)."
    )
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Search executed successfully"),
            @ApiResponse(responseCode = "400", description = "Invalid query parameters")
    })
    @GetMapping("/search")
    public ResponseEntity<List<FlightDto>> search(
            @Parameter(description = "Origin airport code", example = "MAD")
            @RequestParam(required = false, name = "from", defaultValue = "") String from,

            @Parameter(description = "Destination airport code", example = "BCN")
            @RequestParam(required = false) String to
    ) {
        return ResponseEntity.ok(flightService.search(from, to));
    }

    // ✅ POST /flights -> 201 + Location
    @Operation(
            summary = "Create a flight",
            description = "Creates a new flight and returns the created resource."
    )
    @ApiResponses({
            @ApiResponse(responseCode = "201", description = "Flight created successfully"),
            @ApiResponse(responseCode = "400", description = "Invalid request body (validation errors)"),
            @ApiResponse(responseCode = "404", description = "Related resource not found (e.g., airport id does not exist)"),
            @ApiResponse(responseCode = "409", description = "Conflict (duplicate flight code or integrity constraint)")
    })
    @io.swagger.v3.oas.annotations.parameters.RequestBody(
            required = true,
            description = "Flight creation payload",
            content = @Content(
                    schema = @Schema(implementation = CreateFlightRequest.class),
                    examples = {
                            @ExampleObject(
                                    name = "Create example",
                                    value = "{ \"code\": \"IB1234\", \"originAirportId\": 1, \"destinationAirportId\": 2 }"
                            )
                    }
            )
    )
    @PostMapping
    public ResponseEntity<FlightDto> create(@Valid @RequestBody CreateFlightRequest req) {
        FlightDto created = flightService.create(req);

        return ResponseEntity.status(HttpStatus.CREATED)
                // ⚠️ OJO: si tu API no tiene prefijo /api, esto debería ser "/flights/" + created.id()
                .header(HttpHeaders.LOCATION, "/api/flights/" + created.id())
                .body(created);
    }

    // ✅ PUT /flights/{id} -> 200 o 404
    @Operation(
            summary = "Replace a flight",
            description = "Replaces the entire flight resource with the provided payload."
    )
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "Flight replaced successfully"),
            @ApiResponse(responseCode = "400", description = "Invalid request body (validation errors)"),
            @ApiResponse(responseCode = "404", description = "Flight not found"),
            @ApiResponse(responseCode = "409", description = "Conflict (business rule violation)")
    })
    @io.swagger.v3.oas.annotations.parameters.RequestBody(
            required = true,
            description = "Full flight replacement payload",
            content = @Content(
                    schema = @Schema(implementation = UpdateFlightRequest.class),
                    examples = {
                            @ExampleObject(
                                    name = "Replace example",
                                    value = "{ \"code\": \"IB9999\", \"originAirportId\": 1, \"destinationAirportId\": 2 }"
                            )
                    }
            )
    )
    @PutMapping("/{id}")
    public ResponseEntity<FlightDto> replace(
            @Parameter(description = "Flight id", example = "10", required = true)
            @PathVariable Long id,
            @Valid @RequestBody UpdateFlightRequest req
    ) {
        return ResponseEntity.ok(flightService.replace(id, req));
    }

    // ✅ DELETE /flights/{id} -> 204
    @Operation(
            summary = "Delete a flight",
            description = "Deletes the flight identified by the given id."
    )
    @ApiResponses({
            @ApiResponse(responseCode = "204", description = "Flight deleted successfully"),
            @ApiResponse(responseCode = "404", description = "Flight not found"),
            @ApiResponse(responseCode = "409", description = "Conflict (cannot delete due to related data/integrity)")
    })
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(
            @Parameter(description = "Flight id", example = "10", required = true)
            @PathVariable Long id
    ) {
        flightService.delete(id);
        return ResponseEntity.noContent().build();
    }
}
