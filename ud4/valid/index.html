    1️⃣ ¿Qué es @Valid?

    @Valid permite validar automáticamente los datos de entrada de un endpoint REST según las restricciones definidas en los DTOs, devolviendo un error 400 si no se cumplen, sin necesidad de escribir validaciones manuales en el controller.

    @Valid le dice a Spring:

    “Antes de entrar en este método, valida el objeto de entrada según sus anotaciones”.

    Es decir:
    - Valida requests (@RequestBody)
    - Valida params (@RequestParam, @PathVariable)
    - Valida DTOs, no entidades

    Si algo no cumple:
    - 👉 Spring NO entra al método
    - 👉 Devuelve automáticamente 400 Bad Request

    2️⃣ Qué problema soluciona

    ❌ Sin @Valid

    @PostMapping
public ResponseEntity<FlightDto> create(@RequestBody CreateFlightRequest req) {
    // req puede venir con nulls, strings vacíos, números negativos...
}

    Tú tendrías que hacer:
    - if (req == null)
    - if (req.field == null)
    - if (req.field.isBlank())
    - if (req.number < 0)

    👉 Código feo, repetido y propenso a errores.

    ✅ Con @Valid

    @PostMapping
public ResponseEntity<FlightDto> create(
        @Valid @RequestBody CreateFlightRequest req) {
    ...
}

    Y defines las reglas una sola vez en el DTO.

    3️⃣ Cómo funciona el flujo real

    1. Llega la request JSON
    2. Jackson crea el objeto DTO
    3. Spring valida el DTO
    4. Si hay errores:
    5. ❌ no entra al controller
    6. ❌ no entra al service
    7. ✅ devuelve 400 automáticamente

    4️⃣ Validaciones típicas

    Anotación Valida Acepta Rechaza Uso típico
    @NotNull No null "x", 0 null fechas, ids, enums
    @NotBlank String con texto "IB" null, "", " " nombres, códigos
    @Size Valida el tamaño "ABC" "A", "MUY LARGO" para String o colecciones
    @Min Entero mínimo >= 5 0, -1 contadores
    @Max Entero máximo <= 500 999 contadores
    @DecimalMin Decimal mínimo 0.0 -0.1 precios
    @Pattern Regex "M" "Male" formatos
    @Positive > 0 1 0, -1 cantidades
    @PositiveOrZero ≥ 0 0 -1 stock

    También existe @DecimalMax y @DecimalMin, equivalente decimal de @Max y @Min.

    5️⃣ Aplicado a endpoints

    🛩️ POST /api/flights

    DTO de entrada

    public record CreateFlightRequest(

    @NotBlank
    @Size(min = 6, max = 7)
    String flightNumber,

    @NotNull
    LocalDate departureDate,

    @NotNull
    LocalTime departureTime,

    @NotNull
    LocalDate arrivalDate,

    @NotNull
    LocalTime arrivalTime,

    @Positive
    Integer durationMinutes,

    @DecimalMin("0.00") //Acepta: 0, 0.0, 10.50, ❌ Rechaza: -1, -0.01
    BigDecimal basePrice,

    @NotNull
    FlightStatus status,

    @NotNull
    Long airlineId,

    @NotNull
    Long departureAirportId,

    @NotNull
    Long arrivalAirportId
) {}

public record CreateGroupBookingsRequest(
        @NotBlank
        String groupRef,

        @Email
        String contactEmail,

        @NotNull
        @Size(min = 1, max = 9, message = "El grupo debe tener entre 1 y 9 pasajeros")
        List<@Valid PassengerSeatRequest> passengers
) {}

    Controller:

    @PostMapping
public ResponseEntity<FlightDto> create(
        @Valid @RequestBody CreateFlightRequest req) {
    FlightDto created = flightService.create(req);

    return ResponseEntity.status(HttpStatus.CREATED)
            .header(HttpHeaders.LOCATION, "/api/flights/" + created.id())
            .body(created);
}

    📌 Si falta un campo → 400 automático

    public record UpdatePassengerRequest(

    @NotBlank
    String documentNumber,

    @Pattern(regexp = "[MFX]")
    String gender
) {}

    Controller

    @PutMapping("/{id}")
public ResponseEntity<PassengerDto> update(
        @PathVariable Long id,
        @Valid @RequestBody UpdatePassengerRequest req) {

    return ResponseEntity.ok(passengerService.update(id, req));
}
    • 📌 Si documentNumber viene vacío → 400
    • 📌 Si gender no cumple → 400

    6️⃣ Qué NO hace @Valid (muy importante)

    • ❌ No valida lógica de negocio
    • ❌ No comprueba existencia en BD
    • ❌ No detecta duplicados

    Eso sigue yendo en el Service.
